# История диалога: хостинг «ПромВизора»

Сводка разговора от 15.10.2026. Для памяти: что обсуждали, что решили,
какие файлы появились и что осталось сделать.

---

## Задача

Выяснить, как захостить программу «ПромВизор» — контроль простоя
производственной линии по видеопотоку с камеры (FastAPI + SQLite +
Dashboard без сборки + отдельный процесс Telegram-бота).

---

## Что выяснено о проекте при разведке

| Что | Где | Почему важно для хостинга |
|---|---|---|
| FastAPI раздаёт и API, и Dashboard | `app/api/main.py:239` | Один процесс, один порт, ничего менять не надо |
| Dashboard ходит в API по относительным адресам | `web/js/api.js:26` | CORS не нужен, JS править не придётся |
| Конвейер видео живёт **в процессе** | `app/api/runtime.py:31` | uvicorn обязан стартовать с `--workers 1` |
| `API_HOST` по умолчанию `127.0.0.1` | `.env.example:66` | Наружу не достучаться, нужно `0.0.0.0` |
| SQLite-файл `promvizor.db` | `app/core/config.py:66` | Вся история простоя; контейнеру нужен том |
| RTSP открывается через `CAP_FFMPEG` | `app/video/rtsp.py:25` | ffmpeg обязателен, иначе пустой поток без ошибки |
| Видео идёт MJPEG через `<img>` | `web/js/sections.js:241` | WebSocket не используется вообще |
| `FORCED_CAMERA_MODE` перекрывает выбор в UI | `app/core/camera_mode.py:83` | Для боевого сервера фиксирует режим |
| Бот опрашивает API по HTTP, не импортирует | `app/telegram/bot.py:281` | Отдельный процесс, отдельный образ |

---

## Решения

**Хостинг — VPS в облаке, прокси к камере.** Не локальная сеть, не свой
сервер с доменом.

**Docker как основной вариант, systemd как запасной.** Готовы оба.

**WebSocket не нужен.** В проекте его нет ни разу: ни `WebSocket`, ни
`ws://`, ни `EventSource`. Видео — обычный MJPEG, остальное — `fetch`
раз в секунду.

**ISPmanager6 не подходит.** Панель для сайтов, а здесь процесс висит
постоянно и держит камеру часами. Плюс нужны ffmpeg, 1–2 ГБ RAM и
доступ к локальной сети завода — обычный хостинг это не даёт.

## Созданные файлы

Всё новое, код приложения не менялся. Изменены только `README.md`
(добавлен раздел «Развёртывание на сервере») и `.gitignore` (добавлен
`data/`).

| Файл | Назначение |
|---|---|
| `Dockerfile` | Образ backend: API + Dashboard + конвейер |
| `Dockerfile.telegram` | Образ бота отдельно (~80 МБ, без torch) |
| `docker-compose.yml` | Два сервиса, два тома, ffmpeg в образе |

| `deploy/nginx/promvizor.conf` | HTTPS-прокси, отдельный `location /api/video/` |
| `deploy/systemd/promvizor-api.service` | Автозапуск, не от root, изоляция |
| `deploy/systemd/promvizor-telegram.service` | То же для бота |
| `deploy/install.sh` | Развёртывание без Docker одной командой |

### Ключевые решения в конфигурации

* **`--workers 1` везде.** Конвейер в процессе: два воркера — камера
  откроется дважды, второму не достанется, в базу полезут дубли.
* **Рабочий каталог — `data/`, не корень проекта.** Пути `promvizor.db`
  и `camera_mode.json` относительные, а под `ProtectSystem=strict` весь
  `/opt` доступен только на чтение. Отсюда `PYTHONPATH` и симлинк
  `data/demo`.
* **`API_HOST=0.0.0.0` переопределён в compose явно** — `.env.example`
  содержит `127.0.0.1`, и `env_file` перебил бы значение из Dockerfile.
* **`RTSP_URL` и `FORCED_CAMERA_MODE` из compose убраны** — с логином
  и паролем камеры они уехали бы в git.
* **nginx: буферизация выключена для видео.** Иначе кадры копятся и
  отдаются пачкой; multipart без `Content-Length` nginx обрывает
  стандартным таймаутом в 60 секунд.

## Сервер: FirstVDS, 6 ядер / 8 ГБ RAM / 10 ГБ диска / 1 Гбит/с

| Ресурс | Оценка |
|---|---|
| 6 ядер | Хватает для YOLO |
| 8 ГБ RAM | Хватает, детекцию включать можно |
| 10 ГБ диска | **Впритык**: Ubuntu ~2.5 ГБ + образ с YOLO ~2.5 ГБ |
| 1 Гбит/с | Не имеет значения: скорость задаёт камера (2–5 Мбит/с) |

Реальное узкое место — обработка кадров на CPU, а не сеть.

## Что осталось сделать

**1. Проверить доступность камеры — блокирующий шаг.**

```bash
ffprobe -rtsp_transport tcp "rtsp://логин:пароль@192.168.x.x:554/stream"
```

Если сервер в интернете, а камера в локальной сети завода — адрес
`192.168.x.x` недоступен. Варианты: поставить сервер в сеть завода,
связать через WireGuard. Открывать RTSP наружу нельзя: видео с цеха
без авторизации.

**2. Установить.**

```bash
sudo apt update && sudo apt install -y ffmpeg curl
mkdir -p /opt/promvizor        # затем скопировать проект
cd /opt/promvizor
cp .env.example .env
sed -i 's/^API_HOST=.*/API_HOST=0.0.0.0/' .env
sed -i 's|^DATABASE_PATH=.*|DATABASE_PATH=/opt/promvizor/data/promvizor.db|' .env
mkdir -p data && ln -sfn /opt/promvizor/demo /opt/promvizor/data/demo
nano .env                      # RTSP_URL, COST_PER_MINUTE, FORCED_CAMERA_MODE=rtsp
sudo bash deploy/install.sh
sudo systemctl start promvizor-api
curl http://127.0.0.1:8000/api/health
```

**3. Включить детекцию человека** (8 ГБ памяти позволяют):

```bash
sudo -u promvizor /opt/promvizor/.venv/bin/pip install \
  -r /opt/promvizor/requirements.txt
sudo systemctl restart promvizor-api
```

Первый запуск медленный — модель качается и прогревается. Скорость
смотреть через `curl http://127.0.0.1:8000/api/video/state`, поле
`frames`.

**4. Открыть доступ из интернета** — домен + nginx + сертификат:

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo cp deploy/nginx/promvizor.conf /etc/nginx/sites-available/promvizor
sudo ln -s /etc/nginx/sites-available/promvizor /etc/nginx/sites-enabled/
# заменить promvizor.example.ru на свой домен
sudo nginx -t
sudo certbot --nginx -d ваш-домен
```

Порт 8000 наружу не открывать — иначе приложение доступно по http в
обход сертификата.

## Открытые риски

**У приложения нет авторизации.** Любой, кто откроет адрес, увидит
данные о простое и сможет переключить режим камеры. В конфиге nginx
закрыты только `/docs` и `/openapi.json`. Пока не настроен nginx —
не публиковать наружу. После — добавить пароль на `/api/`.

**Диск 10 ГБ.** При нехватке: `sudo apt clean && sudo docker system prune -a`.

**Скорость на CPU.** В README замерено ~0.5 кадра/с на 2 ядрах при
960 px. На 6 ядрах будет лучше, но не 30 — рывки в окне камеры
ожидаемы. Решение (детектировать человека раз в 3–5 кадров) в проекте
не сделано, см. открытые вопросы в README.
